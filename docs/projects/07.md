# Projet 7: Système de Commentaires (60 points)

**Description du projet :**

L'objectif est de développer un système de commentaires interactif, similaire à ce que l'on trouve sur les blogs ou les réseaux sociaux. Les utilisateurs pourront soumettre un nom et un message via un formulaire. Les commentaires soumis seront affichés dynamiquement sur la page. Pour simuler un environnement réel, les interactions avec le serveur (envoi et réception de commentaires) seront simulées à l'aide de `fetch`, et une validation de base sera effectuée sur le formulaire à l'aide d'expressions régulières.

**Instructions de développement :**

Le projet est divisé en modules pour la validation, la communication avec le "serveur" et l'affichage.

**Partie 1: Validation des Entrées**

1.  **Créer un fichier `validator.js`**. Ce module contiendra toute la logique de validation.
2.  **Implémenter des fonctions de validation** :
    *   `isValidUsername(username)`: Vérifie que le nom d'utilisateur n'est pas vide et respecte un format simple (ex: pas de caractères spéciaux). Utilisez une expression régulière pour cette validation.
    *   `isValidComment(comment)`: Vérifie que le commentaire n'est pas vide et ne dépasse pas une certaine longueur.
3.  **Documentation** : Documentez chaque fonction de validation avec JSDoc, en expliquant les règles qu'elle applique.
4.  **Tests** : Créez `validator.test.js`.
    *   Testez des noms d'utilisateur valides et invalides.
    *   Testez des commentaires valides et invalides (trop courts, trop longs).

**Partie 2: Simulation de l'API Serveur**

1.  **Créer un fichier `commentApi.js`**. Ce module simulera les appels réseau pour récupérer et envoyer des commentaires.
2.  **Implémenter les fonctions d'API** :
    *   `getComments()`: Cette fonction utilisera `fetch` pour charger les commentaires depuis un fichier `comments.json` local. Elle doit retourner une promesse qui se résout avec les données des commentaires.
    *   `postComment(comment)`: Cette fonction simulera l'envoi d'un nouveau commentaire. Elle ne fera pas de véritable appel réseau, mais retournera une promesse qui se résout après un court délai (en utilisant `setTimeout`) pour simuler la latence du réseau. La promesse doit se résoudre avec le commentaire qui a été "envoyé".
3.  **Créer un fichier `comments.json`** avec quelques commentaires de départ pour peupler l'affichage initial.
4.  **Documentation** : Documentez les deux fonctions, en expliquant leur nature asynchrone et ce qu'elles simulent.

**Partie 3: Interface Utilisateur et Logique Principale**

1.  **Créer `index.html`** avec un formulaire (champs pour le nom, le commentaire, et un bouton de soumission) et une section pour afficher la liste des commentaires. Prévoyez aussi des zones pour afficher les messages d'erreur du formulaire.
2.  **Créer un fichier `ui.js`**.
    *   `displayComments(comments)`: Prend un tableau d'objets commentaires et les affiche dans le DOM.
    *   `addCommentToDisplay(comment)`: Ajoute un seul nouveau commentaire à la liste existante, pour éviter de tout redessiner.
    *   `displayFormErrors(errors)`: Affiche les messages d'erreur de validation près des champs correspondants.
    *   `clearForm()`: Vide les champs du formulaire.
3.  **Créer `main.js`**.
    *   **Initialisation** : Au chargement, appelez `commentApi.getComments()` et, en cas de succès, utilisez `ui.displayComments()` pour afficher les commentaires initiaux.
    *   **Gestion de la soumission** : Ajoutez un écouteur d'événement au formulaire.
        *   À la soumission, récupérez les valeurs des champs.
        *   Utilisez les fonctions de `validator.js` pour vérifier les entrées.
        *   Si la validation échoue, appelez `ui.displayFormErrors()`.
        *   Si la validation réussit, appelez `commentApi.postComment()`. Une fois la promesse résolue, mettez à jour l'affichage avec `ui.addCommentToDisplay()` et videz le formulaire avec `ui.clearForm()`.

Ce projet vous donnera une expérience pratique de la validation de formulaires côté client et de la simulation d'interactions avec un backend.
