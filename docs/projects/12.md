# Projet 12: Application de Chat avec Salons (150 points)

**Description du projet :**

L'objectif est de construire une application de chat en temps réel permettant à plusieurs utilisateurs de communiquer au sein de différents salons de discussion. L'application utilisera les WebSockets pour une communication bidirectionnelle instantanée entre les clients et le serveur. Le projet simulera la persistance de l'historique des messages et implémentera des notifications pour les nouveaux messages.

**Note sur l'environnement :** Ce projet nécessite un serveur WebSocket. Vous pouvez utiliser une bibliothèque Node.js simple comme `ws` pour le créer, ou utiliser un service tiers qui fournit une API WebSocket de test. Les instructions suivantes se concentrent sur la partie client (navigateur).

**Instructions de développement (partie client) :**

**Partie 1: Connexion au Serveur WebSocket**

1.  **Créer un fichier `socketService.js`**. Ce module encapsulera toute l'interaction avec le serveur WebSocket.
2.  **Implémenter la gestion de la connexion** :
    *   `connect(url)`: Crée une nouvelle instance de `WebSocket` et la retourne.
    *   **Gestionnaires d'événements du socket** :
        *   `onopen`: Géré lorsque la connexion est établie avec succès.
        *   `onmessage`: Géré à chaque fois qu'un message est reçu du serveur. C'est ici que vous traiterez les messages entrants (nouveaux messages de chat, listes d'utilisateurs, etc.).
        *   `onclose`: Géré lorsque la connexion est fermée.
        *   `onerror`: Géré en cas d'erreur de connexion.
3.  **Implémenter les fonctions d'envoi** :
    *   `sendMessage(socket, messageObject)`: Prend un objet message, le transforme en chaîne JSON (`JSON.stringify`), et l'envoie au serveur via `socket.send()`. Un objet message pourrait avoir la structure : `{ type: 'chatMessage', salon: 'general', user: 'Fabrice', text: 'Bonjour !' }`.
    *   `joinRoom(socket, roomName)`: Envoie un message spécial au serveur pour indiquer que l'utilisateur souhaite rejoindre un salon.

**Partie 2: Interface Utilisateur (UI)**

1.  **Créer `index.html`**. La structure doit inclure :
    *   Un formulaire de connexion pour choisir un pseudonyme.
    *   Une liste de salons de discussion disponibles.
    *   Une zone principale pour afficher les messages du salon actif.
    *   Un formulaire de saisie de message avec un bouton d'envoi.
2.  **Créer un fichier `ui.js`**.
    *   `displayMessage(messageObject)`: Ajoute un nouveau message à la zone de chat.
    *   `displayRoomList(rooms)`: Affiche la liste des salons cliquables.
    *   `setActiveRoom(roomName)`: Met en évidence le salon actuellement actif.
    *   `showNotification(messageObject)`: Affiche une notification visuelle (ex: changer le titre de la page) et joue un son si un message arrive dans un salon inactif.

**Partie 3: Gestion de l'État et Logique Principale (`main.js`)**

1.  **Gérer l'état de l'application** : Vous aurez besoin de variables pour stocker :
    *   L'instance du socket.
    *   Le pseudonyme de l'utilisateur.
    *   Le salon actuellement sélectionné.
    *   L'historique des messages (simulé ou reçu du serveur).
2.  **Flux de l'application** :
    *   **Connexion** : L'utilisateur entre un pseudo. Une fois fait, établissez la connexion WebSocket en appelant `socketService.connect()`.
    *   **Réception de messages** : Dans le gestionnaire `onmessage` de votre service :
        *   Analysez le message JSON reçu (`JSON.parse`).
        *   Selon le `type` du message (`newChatMessage`, `userListUpdate`, `roomHistory`, etc.), appelez la fonction `ui.js` appropriée pour mettre à jour l'interface.
        *   Implémentez la logique de notification : si le message concerne un salon qui n'est pas actif, déclenchez une notification.
    *   **Changement de salon** : Lorsque l'utilisateur clique sur un salon, appelez `socketService.joinRoom()` et mettez à jour l'UI pour afficher les messages de ce salon (qui devraient être envoyés par le serveur suite à la demande de `join`).
    *   **Envoi de message** : Lorsque l'utilisateur envoie un message, créez l'objet message, et passez-le à `socketService.sendMessage()`. Le serveur le recevra et le diffusera aux autres clients (y compris vous-même), et c'est le `onmessage` qui déclenchera l'affichage.

**Partie 4: Simulation de la Persistance**

*   Pour simuler la persistance de l'historique sans un vrai backend, vous pouvez faire en sorte que votre "serveur" (ou une simulation dans le client) envoie un jeu de messages prédéfinis chaque fois qu'un utilisateur rejoint un salon. Vous pouvez stocker ces messages dans des fichiers JSON (`general-history.json`, `random-history.json`).

Ce projet est une introduction avancée aux applications web temps réel et à la communication événementielle.
